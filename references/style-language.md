# Style Language

## Overall character

Chris's recurring visual language is:
- editorial;
- architectural;
- product-first;
- neutral/premium;
- information-dense without being crowded;
- visually strong without looking ornamental.

The interface should feel considered and specific to the product.

## Color

Default to a restrained base:
- near-black;
- white/off-white;
- warm or cool greys;
- one restrained accent when the product needs it.

Use color to indicate:
- action;
- status;
- selection;
- emphasis;
- brand identity.

Do not use generic purple because it "looks tech".
Do not add gradients merely to make a surface feel premium.
Do not depend on glow for depth.

If the actual product or brand has meaningful color, keep it.

## Typography

Use typography to create hierarchy before adding boxes.

Recurring preferences:
- strong, readable titles;
- clean sans-serif body/navigation;
- quieter metadata;
- compact uppercase/letter-spaced labels where useful;
- confident size contrast;
- tighter tracking on large titles;
- enough scale on tablet/desktop to avoid weak, tiny interfaces.

Avoid:
- every text level being similar in size;
- giant theatrical type with no information purpose;
- tiny body text used as a "minimal" aesthetic;
- decorative display type everywhere.

An expressive/script/display face can be used for a wordmark or one intentional brand role, but not as the default UI font if it hurts legibility.

## Surfaces and geometry

Prefer:
- clean planes;
- structural lines;
- subtle borders;
- deliberate whitespace;
- stable grids;
- restrained shadows.

Rounded corners are allowed when they fit the product, but do not turn every block into a large rounded card.

Use pills for things that are actually pill-like:
- compact controls;
- status;
- filters;
- tags.

Do not make every button, section, statistic, and image a pill.

## Glass, blur, and effects

Glass/frost can be useful for:
- temporary overlays;
- floating chrome;
- modal separation;
- light/dark parity;
- contextual depth.

It is not the default design language.

Use it only when the interface gains clarity from it.

Likewise:
- gradients;
- heavy shadows;
- glow;
- blur;
- decorative noise

must have a specific purpose.

## Imagery

Real work should be visually dominant.

Use:
- actual screenshots;
- real media;
- actual avatars;
- real product cards;
- real interface states.

Preserve original media quality and aspect ratio where possible.

Do not:
- fabricate product thumbnails;
- use irrelevant stock imagery;
- generate fake UI;
- distort media;
- place controls over important visual/text content.

## Density

The target is not "lots of whitespace" or "lots of information".

The target is useful density with clear reading order.

If the screen feels crowded:
- remove duplicate copy;
- reduce simultaneous messages;
- group related data;
- improve scale contrast;
- give the primary visual more room.

If the screen feels empty:
- do not add decoration;
- increase the value of what is already there.
